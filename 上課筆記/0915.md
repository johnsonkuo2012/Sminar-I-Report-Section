## 筆記內容

### 2. 背景

- 多處理器／多電腦系統越做越大，節點之間用 interconnection network（互連網路）連接
- 規模變大，再加上網路攻擊，節點一定會故障
- 單顆處理器可靠度 99.99%
- 需要一次找出好幾個壞點的方法

### 3. 系統級診斷（system-level diagnosis）

- 節點互相測試，可以找出所有的壞節點
- syndrome（症候）= 所有測試結果的一組組合

4 點環 a-b-c-d，雙向互測共 8 個測試：
- c 壞：b→c、d→c 一定是 1，c→b、c→d 不確定，其他都是 0，共 4 種 syndrome
- b 壞：a→b、c→b 一定是 1，b→a、b→c 不確定

### 4. PMC 模型

Preparata, Metze, Chien (1967), IEEE Trans. Comput. 16, 448–454
- PMC 是三個作者姓氏的縮寫，C 是華人學者錢天聞（Robert Tienwen Chien）

由中央仲裁者（centralized arbiter）看 syndrome，判斷每個節點是好是壞

### 5. 診斷度 t（diagnosability）

- 壞點太多的話，仲裁者判斷不出來
- t = 最多可以有幾個壞點

### 6. 條件診斷度（conditional diagnosability）

- 原本的 t 不會限制壞點怎麼分布，最壞情況是某個點的鄰居全部壞掉
- 實際上這種情況幾乎不會發生
- 排除這種情況後，很多不確定的結果可以刪掉，能接受的壞點就變多，常常是好幾倍

## 名詞解釋

| 名詞 | 英文 | 解釋 |
|---|---|---|
| 節點 | node | 網路裡的一台處理器或電腦 |
| 互連網路 | interconnection network | 把很多節點連在一起的網路，例如超立方體、星狀網路 |
| 故障節點 | faulty node | 壞掉的節點，筆記裡簡稱壞點 |
| 系統級診斷 | system-level diagnosis | 讓節點互相測試，找出哪些節點壞掉 |
| 症候 | syndrome | 所有節點互測結果的一組組合 |
| PMC 模型 | PMC model | 最早的診斷模型，好的節點測出來是對的，壞的節點測出來 0 或 1 都有可能 |
| 中央仲裁者 | centralized arbiter | 負責看 syndrome，判斷每個節點是好是壞 |
| 診斷度 | diagnosability | 最多可以有幾個壞點，仲裁者還能全部正確找出來 |
| 條件診斷度 | conditional diagnosability | 假設每個節點至少有一個好鄰居時的診斷度，通常比原本高很多 |
